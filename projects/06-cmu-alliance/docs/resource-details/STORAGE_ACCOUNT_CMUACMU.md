# Azure 資源明細：Storage Account (cmuacmu)

本文件詳細記錄 `cmuacmu` 儲存體帳戶的組態設定。此帳戶為 `CMU Alliance` 專案的核心儲存體，其設定規格與 `weigong` 帳戶保持一致，確保高效能與高可用性。

## 1. 基本資訊

| 項目 | 值 |
| :--- | :--- |
| **名稱** | `cmuacmu` |
| **資源群組** | `cmua-cmu` |
| **位置** | `Japan East (japaneast)` |
| **帳戶種類** | `StorageV2 (一般用途 v2)` |
| **複寫** | `區域備援儲存體 (ZRS)` |
| **建立時間** | `2026/04/15` |

---

## 2. 檔案服務設定 (Azure File Share)

*   **檔案共用名稱**：`cmuacmu`
*   **存取層**：`交易最佳化`
*   **配額**：`100 TiB` (102400 GiB)
*   **通訊協定**：`SMB`
*   **共用 URL**：`https://cmuacmu.file.core.windows.net/cmuacmu`
*   **資料保護**：
    *   **虛刪除 (Soft Delete)**：已啟用（保留 7 天）。
    *   **備份服務**：部署中（預期將提供定期快照保護）。

---

## 3. 安全性與網路組態 (比照 weigong 規範)

為了符合專案安全標準，本帳戶遵循以下規範：

*   **傳輸安全**：強制要求 TLS 1.2 以上版本，且所有連線必須經過加密。
*   **網路隔離**：建議比照 `weigong` 設定，僅允許來自 `cmua-cmu` 虛擬網路 (VNet) 的私人端點連線。
*   **身分驗證**：目前使用儲存體帳戶金鑰 (Account Key) 進行連線，未來可考慮升級至 Azure AD 型存取。

---

## 4. 維運操作建議

1.  **掛載路徑**：建議將此檔案共用掛載至 `cmua-cmu-ap1` 與 `ap2` 的 `Z:` 或 `W:` 磁碟機。
2.  **監控**：建議針對「交易量」與「延遲」設定告警，特別是醫療影像或大量日誌寫入情境。
3.  **復原測試**：備份服務完成後，應定期進行單一檔案還原測試，驗證虛刪除與備份的有效性。

---

## 5. 常見問題 (Troubleshooting)

| 問題 | 可能原因 | 解決方法 |
| :--- | :--- | :--- |
| **無法掛載共用目錄** | 通訊埠 445 被 ISP 封鎖 | 確保在 Azure 內網執行掛載，或確認 NSG 已開放相關流量。 |
| **備份失敗** | 部署尚未完成 | 確認 Azure Backup 策略已正確關聯至該檔案共用。 |
| **配額不足** | 儲存量超出 100 TiB | 於 Portal 手動調整配額限制（最高支援 100 TiB）。 |
